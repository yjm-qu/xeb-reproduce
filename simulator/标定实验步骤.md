# XEB 模拟器标定实验步骤

## 目的

建立 Depolarizing(p) 的 p 值与实际门错误率 ε 的对应关系，用于 XEB 实验。

## 需要的数据

- 单门：p=0.0016 对应的 epsilon
- 双门：p=0.0062 对应的 epsilon

这两个 epsilon 值将用于 xeb_v2.py 的噪声参数。

---

## 实验步骤（shots=100000）

### 单门标定

```bash
# 1. Sanity check（验证代码逻辑对）
# 期望：epsilon ≈ 0，显示 PASSED
python calibrate.py --p 0 --gate X --shots 100000

# 实测结果：p=0.0 → epsilon=0.0000 (PASSED)
```

```bash
# 2. 目标 p 标定（得到论文 p=0.0016 对应的实际 epsilon）
# 期望输出格式：p=0.0016 → epsilon=X.XXXX; p/epsilon=X.XXXX
# 理论 p/ε ≈ 2.0（实际比值可能不同，这正是标定的意义）
python calibrate.py --p 0.0016 --gate X --shots 100000

# 实测结果：p=0.0016 → epsilon=0.0009; p/epsilon=1.7778
```

### 双门标定


## 反向标定：已知目标 ε，求对应 p

### 背景

论文的做法是分两个阶段：
1. **Hardware characterization**：先用 RB 实验一次性测出错误率 ε（这是硬件参数，固定不变）
2. **XEB 实验阶段**：不再重新测错误率，直接用这个固定值算预测线

> 参考论文 P507："Having found the error rates of the individual gates and readout, we can model the fidelity of a quantum circuit as the product of the probabilities of error-free operation of all gates and measurements."

所以我们复现论文，也要先一次性标定出 p → 写进 xeb_v2.py → α_f 永远用论文的 ε 值。

### 做法

使用多 p 扫描，画出 p-ε 关系曲线，然后反推目标 ε 对应的 p 值。

注意：由于 uniqc bug，同一进程内连续调用会互相影响，必须用子进程隔离。

### 实验结果

| 目标 ε | 门类型 | p | 实测 epsilon |
|--------|--------|------|--------------|
| 0.0016 | 单门 | 0.0028 | 0.0016 ✓ |
| 0.0062 | 双门 | 0.0071 | 0.0062 ✓ |

### 结论

**用于 xeb_v2.py 的参数（更新）：**
- 单门：p = 0.0028（让实际 ε ≈ 0.0016）
- 双门：p = 0.0071（让实际 ε ≈ 0.0062）

alpha_f 计算时仍用论文的 ε=0.0016 和 ε=0.0062。

## uniqc 库 Bug 完整记录

### 1. Bug 现象描述

同进程内连续调用含 TwoQubitDepolarizing 的模拟时：
- 先跑 p=0 → 结果正确（无噪声，100% 理想结果）
- 再跑 p>0 → 结果仍然像 p=0（噪声不生效，epsilon=0）

### 2. Bug 触发条件

只有满足以下条件才会触发：
1. 同进程内连续调用
2. 先调用 p=0，后调用 p>0

如果单独直接跑 p>0（不先跑 p=0），结果正常。

**新发现：同进程内任何不同的 p 值连续调用都会互相影响。**
```python
# 现象：同进程内循环跑不同 p 值
for p in [0.01, 0.008, 0.006]:
    # 结果：所有 p 都返回类似的 epsilon（约 0.008）
    # 预期：p 越大 epsilon 越大
```

验证：
- p=0.01 → epsilon=0.00811
- p=0.008 → epsilon=0.00817（应该更小）
- p=0.006 → epsilon=0.00812（应该更小）

**结论：** bug 不仅影响"p=0 → p>0"，而是影响同进程内所有 TwoQubitDepolarizing 调用。必须用子进程隔离才能得到正确结果。

### 3. 影响范围

测试了以下双门，全部受影响：
- ISWAP
- CZ
- CNOT
- SWAP

单门不受影响。

### 4. 详细验证过程

#### 验证1：同进程状态污染
```python
# 脚本
def run_two_qubit(p):
    em = ErrorLoader_GateTypeError(
        generic_error=[Depolarizing(p=0)],
        gatetype_error={'ISWAP': [TwoQubitDepolarizing(p=p)]}
    )
    sim = NoisySimulator(backend_type='statevector', error_loader=em)
    circuit = Circuit(2); circuit.x(0); circuit.ISWAP(0,1); circuit.measure(0); circuit.measure(1)
    result = sim.simulate_shots(circuit.originir, shots=10000)
    return result

# 同进程内连续调用
print(run_two_qubit(0))      # 先跑 p=0
print(run_two_qubit(0.0062)) # 再跑 p=0.0062
```
**结果：**
- p=0 时：{2: 10000}（全对，epsilon=0）
- p=0.0062 时：{2: 10000}（应该是 {2: 9945, 0:22, 1:15, 3:17}）

#### 验证2：单独跑 vs 连续跑
- 单独跑 p=0.0062：epsilon=0.0055 ✓
- 同进程先 p=0 再 p>0：epsilon=0 ✗

#### 验证3：单门用 gatetype_error
```python
# 单门也用 gatetype_error 字典
em = ErrorLoader_GateTypeError(
    generic_error=[Depolarizing(p=0)],
    gatetype_error={'X': [Depolarizing(p=p)]}
)
```
**结果：** 正常，问题不在 gatetype_error 字典本身

#### 验证4：其他双门
| 门 | p=0 | p=0.5 | 期望 | 结果 |
|-----|------|--------|------|------|
| CZ | {1:1000} | {1:1000} | 应有混合 | 噪声不生效 |
| CNOT | {3:1000} | {3:1000} | 应有混合 | 噪声不生效 |
| SWAP | {2:1000} | {2:1000} | 应有混合 | 噪声不生效 |

### 5. 根因猜测

另一个智能体的分析：

> uniqc 库的 TwoQubitDepolarizing 在 native 层（C++/pybind11）有模块级缓存，第一次创建后参数被"钉死"。

可能的原因（按概率排序）：
1. ErrorLoader_GateTypeError 在 native 层维护全局 dict，第二次创建时直接复用第一次的 noise 对象
2. TwoQubitDepolarizing.__init__ 在 native 层只解析一次 p 参数，后续忽略新 p
3. NoisySimulator.simulate_shots 内部用 weakref 缓存了第一次调用的 noise_model

### 6. xeb_v2.py 是否受影响

**不影响。** 因为 xeb_v2.py 直接用 `TwoQubitDepolarizing(p=EPS2)` 赋正值，不会先跑 p=0 再跑 p>0，所以 Bug 不会触发。

实测验证：
```
直接跑 p=0.0062（不先跑 p=0）: 0.0055
直接跑 p=0.0052: 0.0048
```
结果正常。

### 7. 建议的定位实验（来自另一个智能体）

如需进一步精确定位根因，建议：

**实验 A：** 定位是 ErrorLoader 还是 NoisySimulator 复用
```python
em1 = ErrorLoader_GateTypeError(..., gatetype_error={'ISWAP': [TwoQubitDepolarizing(p=0)]})
em2 = ErrorLoader_GateTypeError(..., gatetype_error={'ISWAP': [TwoQubitDepolarizing(p=0.0062)]})
sim1 = NoisySimulator(..., error_loader=em1)
sim2 = NoisySimulator(..., error_loader=em2)
# 两个 sim 都新建
```

**实验 B：** 定位 TwoQubitDepolarizing 对象复用
```python
td0 = TwoQubitDepolarizing(p=0)
td0062 = TwoQubitDepolarizing(p=0.0062)
# 分别传入不同的对象
```

**实验 C：** 定位 ErrorLoader 内部缓存
```python
em = ErrorLoader_GateTypeError(..., gatetype_error={'ISWAP': [TwoQubitDepolarizing(p=0)]})
# 跑完后修改 em 内容
em.gatetype_error['ISWAP'] = [TwoQubitDepolarizing(p=0.0062)]
```

**实验 D：** 打印 id() 看对象身份
```python
td1 = TwoQubitDepolarizing(p=0)
td2 = TwoQubitDepolarizing(p=0.0062)
print(id(td1), id(td2))  # 看是否同一个 native 对象
```

### 8. Workaround 方案

#### 方案 A（推荐）：分两次跑
```bash
python calibrate.py --p 0.0062 --gate ISWAP --shots 100000  # 先跑目标
python calibrate.py --p 0 --gate ISWAP --shots 100000       # 再跑 sanity
```

#### 方案 B：每次 reload 模块
```python
import importlib, uniqc, uniqc.simulator
importlib.reload(uniqc)
importlib.reload(uniqc.simulator)
```
代价：慢

#### 方案 C：subprocess 隔离
每次模拟用独立 Python 进程。代价：非常慢，不实用。
